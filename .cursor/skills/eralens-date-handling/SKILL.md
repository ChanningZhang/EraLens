# EraLens 日期处理

所有历史日期工作统一遵守本 Skill。事件、在位、王朝、都城、人物日期、关系日期和数据修复流程均须链接并遵循本文件。

## 日期与精度

- 每次录入、修改或复核日期，都应尽可能从可靠史料获取最高可信精度；史料能可靠确认月日时不得只保留年份。
- 日期值采用 `HistoricalDate = { year, month, day?, confidence }`。年月日只记录可确认的历法日期；每个起止端点独立填写置信度，不得用一条记录的总精度覆盖端点差异。
- `year` 使用项目带符号公历纪年，公元前年份为负数；AbsMonth 使用共享 `absMonth()`。
- 先辨明历法。农历月日不得直接作为公历录入；只有可靠换算后才写换算后的公历月日，并保留原记载、历法和换算依据。不能可靠换算时保留原文并降低精度。
- 日期精度指史料日期本身的粒度；confidence 指该日期主张的可信状态，二者不可互相替代。

## 年代依据的选择

- 每个端点采用当前可获得的最可信年代依据。比较原始记载、学术系年、可靠年表和通行百科的具体年份与证据；有出处、经交叉核对且未被更强证据否定的推定年份，优先于系统关联定位和世次均分。来源载体本身不决定可信度，多个互相转载的页面也不算独立证据。
- 存在异说或尚未追溯完整换算过程，不等于该年份毫无依据。来源明确给出的具体年份可按证据强弱采用 `approximate_*`，不必达到确定日期的证明门槛；不能仅因不够确定，就继续保留更低可信的均分坐标。用户明确选择的年代方案按其要求采用，并记录来源、异说和置信度。
- 来源冲突时逐端点比较世系、共时记录、在位年数和年代框架，采用解释力更强的依据；不要照抄内部矛盾的整表，也不要将有年次依据的端点退回均分。只在没有可采用的具体日期时使用关联推断；世次均分是最后的定位手段。

## Confidence

端点使用以下八类：

| confidence | 含义 | 示例展示 |
| --- | --- | --- |
| `day` | 确定到日 | `685年9月27日` |
| `month` | 确定到月 | `685年9月` |
| `year` | 确定到年 | `685年` |
| `approximate_day` | 推定到日 | `约685年9月27日` |
| `approximate_month` | 推定到月 | `约685年9月` |
| `approximate_year` | 有出处的推定或所采争议年代，精度到年 | `约685年` |
| `interpolated_by_other` | 依明确关联史料或共时记录推定 | `?` |
| `interpolated_by_generation` | 连续世系在可靠双端锚点间按世次均分 | `?` |

确定类显示日期并使用竖线；近似类显示“约”并使用竖线；插值类显示“?”并使用波浪线。日期精度与置信度不一致时，以来源可支持的较低精度记录；不得用空间定位精度表示日期置信度。

## 相邻在位边界

- 相邻且构成同一继位交接的在位记录，以精度更高的一侧为参考标准，统一前任终点与后任起点的日期依据、confidence 和边界展示。先按年代依据的可信程度取舍（可采的确定日期、有出处的近似日期优先于关联推算和世次均分），同等可信条件下再比较日、月、年精度；不能因插值坐标含月日就视为精度更高。
- 仅统一交接处的两个端点，不提升另一端或整段在位的精度。例如近似年份锚点与世次均分段相接时，均分段贴近锚点的端点采用该近似依据、显示“约”和竖线；其余插值端点仍显示“?”和波浪线。
- 统一的是交接依据，不要求两个端点的存储日期字面相同。按 `timelineOwnership.ts` / `timelineIntervals.ts` 裁定归属，保留死年归旧王、逾年起算及混合精度规则，不手写日期加减。
- 只适用于已核实的连续接续；真正并立、无国君空档或继位关系未明的记录不得强行统一。修改写回导入源并留据，不在渲染层临时覆盖低精度端点。

## 不确定区间的展示与都城归属

- 起止任一端点属于 `approximate_*` 或 `interpolated_*` 时，不展示由该区间坐标计算出的确定时长；详情、tooltip、都城任期及裁剪后的区间遵循同一规则，禁止出现“? — ? · 39年”这类展示。
- 在位或都城时段任一端点不确定时，都城信息只保留在王朝级别，不下沉到每段在位期间；不得通过推算区间重叠或显式 reign `location_mapping` 关联绕过此规则。不确定在位的详情不生成都城任期区块，仍保留按端点置信度展示的在位事实。
- 日期文字统一调用 `formatHistoricalDate()`；区间置信度统一调用 `hasUncertainDateRange()`。推算坐标可继续用于时间轴定位，但不能作为确定时长或君主都城归属的依据。

## 推断与插值

- 关联推断必须存在明确的对应关系或共时依据，参照日期必须属于前六类确定/近似 confidence；禁止循环推断。
- 有来源直接给出且经取舍采用的具体年份使用 `approximate_year`；只有为定位而间接分配的坐标才使用 `interpolated_*`。不得把已有来源年份当成均分结果，也不得只换 confidence 而继续沿用较差的旧坐标。
- `interpolated_by_generation` 仅用于连续世系且有可靠双端锚点、可按世次均分的区间。世系中断、锚点不足或仅依传统积年时不得插值。
- 无出处或已被更强证据否定的传统积年不作为日期依据；有出处但尚存争议的系年按上述规则取舍，不能一律撤下并换成均分。无法采用任何具体年代时保留人物、世系和可证事实，并说明依据不足。
- 推断结果显式写入导入缓存；依据、历法和取舍写入 `manifest.notes`，来源写入 `manifest.sources`。

## 事件

- 事件只使用 `point` 和 `span`，不使用 `circa`；不增加 `displayScale`。日期不确定性由端点 confidence 表达。
- 持续时间不足一个日历年时使用 `point`；满一个日历年及以上的真实持续过程使用 `span`。不得从占位年月推算真实时长。
- 短事件优先使用史料支持的代表时点，否则使用核实后的起点；保留原起止叙述和取舍依据于 `date_note`。
- `span` 表达实际持续过程，不可仅因日期模糊而使用；模糊点事件仍为 `point` 并设置近似 confidence。
- 年精度 point 的轴时点使用该年 12 月桶右缘；占位月份不得显示为史料已知月份。

## 共享实现与复核

- 日历区间归属调用 `packages/shared/src/timelineOwnership.ts` 和 `timelineIntervals.ts`；调用侧不得重写端点比较或手工加减年月。
- 先记录原值和来源，再逐端点复核；不得用批量字段映射冒充史料复核。无改动、依据不足、待核及暂缓记录都要保留 ID、结论和理由。
- 日期新增、修改或复核时同步核对并更新来源，按 [来源维护](../eralens-period-import/SKILL.md#来源维护) 维护 `manifest.sources` 与适用条目的 `links`，验收时检查详情“来源”栏。
- 真实数据只改 `data/imports/{slug}/cache.json`，执行全量所有权审计、统一生成器、导入校验，再增量更新数据库。
- 数据库精度旧列只在用户校验迁移报告并明确确认通过后，才可在独立 DROP 迁移中删除。
